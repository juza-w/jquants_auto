# 株式分析・アラートシステム

日本株・米国株の「データ取得 → 指標 → シグナル → 判断案 → 通知」を自動化する。
**発注はしない**（人間が証券会社で手動で行う）。

## 毎日の流れ

1. 引け後に GitHub Actions が起動（日本 18:17 JST / 米国 NY時間 17:37〜18:37）
2. 株価を更新 → ルールでシグナルを作る（終値までの情報だけ。買い・売りは翌営業日の始値を想定）
3. シグナルが出た銘柄だけ Claude に渡す: Web 検索でニュースを調べ、数値データと合わせて判断案（JSON）を作る
4. Discord に通知し、判断案を `proposals` テーブルに記録
5. 後日、各判断案の「その後の値動き」（5/20/60営業日後）を自動で埋める → 通知の成績を検証できる

銘柄の入れ替え判断は週の最初の営業日だけなので、新規の買いは主に週1回。それ以外の日は
売り（SMA200割れ・損切り到達）と保有状況の報告になる。
通知に出る「モデルポートフォリオ」はルールどおり売買したと仮定した仮想運用で、実際の保有とは別。

## GitHub Actions の設定（初回だけ）

リポジトリの Settings → Secrets and variables → Actions → New repository secret で3つ登録する:

| 名前 | 値 |
|---|---|
| `JQUANTS_API_KEY` | J-Quants の API キー |
| `ANTHROPIC_API_KEY` | Claude API のキー |
| `DISCORD_WEBHOOK_URL` | Discord の Webhook URL |

動作確認: Actions タブ → daily-alert → Run workflow。`as_of` に月曜の日付を入れると、その日の
シグナルで通知まで試せる。記録は `state` ブランチの `alerts.db` に保存される。

SELECT date, adj_close FROM daily_bars WHERE symbol = '7203.JP' ORDER BY date DESC LIMIT 20;

## データの決まりごと

- `open/high/low/close/volume` は調整前（その日に実際に付いた値）。
- `adj_close` は**分割・併合のみ**調整した終値。配当は調整しない（J-Quants の `AdjC` と同じ定義）。
  Yahoo は逆に価格が分割調整済みで返るので、`Stock Splits` から調整前の値を逆算して揃えている。
- 毎回、保存済みの直近10営業日を取り直して上書き。その範囲で調整済み終値が0.1%超ずれていたら
  分割とみなして全期間を取り直す。
- J-Quants: Light プラン（5年分・遅延なし・60リクエスト/分）。`.env` の `JQUANTS_REQUESTS_PER_MIN` をプランに合わせる。
- 米国株は取引時間中（NY 16:30 前）に実行すると当日の未確定の足を捨てる。

## 用語メモ

- **調整済み株価**: 株式分割（例: 1株→5株）で株価は見かけ上1/5になる。過去の値段を同じ比率で直して
  つなげたものが調整済み株価。これを使わないと分割を「暴落」と誤認する。
- **SMA（単純移動平均）**: 直近N日の終値の平均。SMA200より上なら長期の上昇トレンドとみなす。
- **RSI**: 直近14日の上げ幅と下げ幅の比（0〜100）。70超は買われすぎ、30未満は売られすぎの目安。
- **ATR**: 1日の値動きの大きさの平均。損切り幅や買う株数を「その銘柄の普段の動き」に合わせるのに使う。
- **売買代金**: 終値×出来高。大きいほど売買しやすい（流動性が高い）。
- **モメンタム**: 最近上がった銘柄は続けて上がりやすい、という経験則。直近1か月は逆に動きやすいので除く。
- **最大ドローダウン**: 資産が最高額から最も大きく減った割合。耐えられる損失の目安。
- **先読みバイアス**: その時点では知り得ない情報で売買してしまう検証上の誤り。本システムは
  「終値で判断 → 翌営業日の始値で約定」として避けている。
- **生存者バイアス**: 「今の」大型株だけで過去を検証すると、落ちぶれた銘柄が抜けているので成績が良く見える。

## バックテスト結果（2026-11-13 実行）

仮定: 日本 資金300万円・手数料0.1%・スリッページ0.1% / 米国 資金3万ドル・手数料0.5%・スリッページ0.1%（すべて片道）。
対象: 日本 TOPIX100、米国 大型50銘柄。BM = ベンチマーク（1306 / SPY を持ち続けた場合）。配当は戦略・BMとも含めない。

**結論: ベンチマークに勝てると検証できた戦略はまだない。通知は参考情報として扱うこと。**

### 戦略v2（現在の設定）

v1 からの変更: 手仕舞いを SMA50 → SMA200、上位10で買い30位以内なら持ち続ける、銘柄数 5 → 10。
作る用期間だけで96通りを比べ（`python scripts/grid_search.py`）、日米どちらでも同じ向きに効いた項目だけ変えた。
入れ替えの判断日は「週の最初の営業日」（過去の情報だけで判定できるため。本番と同じ）。

| 市場 | 期間 | 年率 | 最大DD | 勝率 | 平均利益 | 平均損失 | 取引回数 | BM年率 | BM最大DD |
|---|---|---|---|---|---|---|---|---|---|
| JP | 作る用 2022-12〜2024-11 | +21.3% | -24.7% | 26.8% | +17.0% | -6.1% | 82 | +16.4% | -23.4% |
| JP | **検証用** 2024-12〜2026-11 | +8.1% | -19.3% | 25.5% | +33.2% | -6.8% | 55 | +21.5% | -17.7% |
| US | 作る用 2011〜2019 | +12.3% | -20.2% | 32.6% | +35.3% | -5.8% | 270 | +10.9% | -20.2% |
| US | **検証用** 2020〜2026-11 | +4.1% | -39.0% | 21.3% | +42.7% | -6.3% | 263 | +13.1% | -34.1% |

読み方（信用してよいのは検証用の行だけ）:

- **日米とも検証用でBMに負けた。**
- 入れ替えの判断日を「週の最終営業日」にした版では、検証用が 米国 +15.5% / 日本 +13.9% だった。
  判断日を1営業日ずらしただけで結果が大きく変わるのは、成績が偶然に左右されている証拠。
  本当に優位性があるルールは、この程度の変更では崩れない。
- 対象が「今の大型株」なので生存者バイアスで有利なはずなのに負けている。
- 勝率は21〜33%と低く、少数の大きな利益で稼ぐ型。連敗が続く時期がある。
- 検証用期間はもう使えない（見ながら直すと検証にならない）。今後の検証は実運用の記録（proposals）で行う。
